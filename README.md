# אפליקציית ערב פוקר: תשתית (שלב 1)

המסמך הזה מכסה את מה שנבנה עד עכשיו: מסד הנתונים, ההרשאות, מנוע החישובים, והוראות ההתקנה. ממשק המשתמש (Expo) הוא השלב הבא.

## מה יש בתיקייה

| קובץ | מה הוא עושה |
|---|---|
| `supabase/migrations/20261003000000_init.sql` | כל מסד הנתונים: 9 טבלאות, הגנות שלמות נתונים, RLS, Views לסיכומים ולליגה, ופונקציות להצטרפות לקבוצה, לאישור חברים ולסגירת ערב |
| `src/core/settle.ts` | מנוע החישובים: יתרות, המרת צ'יפים לשקלים, איזון יחסי, מינימום העברות, חלוקת קופה במזומן, ופרסי טורניר |
| `src/core/settle.test.ts` | 10 בדיקות, כולל ערב הדוגמה ו-2,000 ערבים אקראיים |
| `supabase/tests/` | 36 בדיקות של מסד הנתונים על Postgres אמיתי: הרשאות, ניסיונות עקיפה וסגירת ערב |

## מה המערכת אוכפת (נבדק)

| כלל | איך |
|---|---|
| רק הבנקאי מזין | RLS: צופה שמנסה להכניס כסף נחסם |
| את העבר לא משנים | אין UPDATE ואין DELETE ביומן. טעות מתוקנת ב-reversal, והטעות נשארת מתועדת |
| ערב סגור קפוא | אחרי `close_game` אין שום שינוי |
| סגירה רק כשמאוזן | הקופה חייבת להיות שווה לסך היציאות, וההתחשבנות חייבת להתאים ליומן שקל בשקל |
| מקסימום ריבאיים | נאכף בשרת |
| צ'יפים לשקלים | השרת מחשב בעצמו ודוחה סכום שלא תואם את מספר הצ'יפים |
| קבוצות סגורות | זר לא רואה קבוצה, שחקנים, משחקים או פרופילים |
| שידור חוזר ללא כפילות | אותו אירוע שנשלח פעמיים מהטלפון נרשם פעם אחת |

## העלאת מסד הנתונים ל-Supabase

```bash
supabase login
supabase link --project-ref <PROJECT_REF>      # מופיע ב-Settings > General
supabase db push                               # מריץ את קובץ ה-migration
```

לבדוק אחרי ההעלאה, ב-Table Editor:
- 9 טבלאות קיימות, ובכולן מופיע "RLS enabled".
- ב-Database > Publications, הפרסום `supabase_realtime` כולל את games, game_players, ledger_entries ו-settlements.

## כניסה עם Google

1. ב-Google Cloud Console: פרויקט חדש, OAuth consent screen, ואז Credentials > OAuth Client ID מסוג Web application.
2. ב-Authorized redirect URI להדביק את הכתובת ש-Supabase מציג ב-Authentication > Providers > Google.
3. ב-Supabase: להפעיל את Google ולהדביק Client ID ו-Client Secret.
4. ב-Authentication > URL Configuration: להוסיף את כתובות האפליקציה. נגדיר אותן בשלב הבא.

## מפתחות: מה נכנס לאפליקציה ומה לא

| מפתח | איפה |
|---|---|
| Project URL ו-anon key | באפליקציה. הם גלויים בכוונה, וההגנה היא ה-RLS |
| service_role key | **אף פעם לא באפליקציה.** רק ב-GitHub Secrets, לגיבוי |
| Database password | במנהל סיסמאות |
